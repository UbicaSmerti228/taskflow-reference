# TaskFlow — эталонное решение

Трекер задач, который проходит через всю карту [Go Backend Roadmap](https://ubicasmerti228.github.io/go-roadmap/). Каждая версия проекта закрывает чек-лист своего этапа и помечена тегом.

Сначала сделай версию сам, потом сравни с этой. Совпадать не обязано: здесь один из разумных вариантов, а не единственно верный.

## Версии

| Тег | Этап карты | Что внутри |
|-----|------------|------------|
| `v0.1` | 1. Фундамент Go | CLI и HTTP на стандартной библиотеке, задачи в JSON-файле |
| `v0.2` | 2. REST, конкурентность и алгоритмы | Полный CRUD с пагинацией, единый формат ошибок, OpenAPI, воркер напоминаний |
| `v0.3` | 3. Docker и PostgreSQL | Хранилище в PostgreSQL, миграции, интеграционные тесты, Dockerfile и compose |
| `v0.4` | 4. Сервис: фреймворк, безопасность, Redis, деплой | Слои, Gin, логи, регистрация и вход, кэш в Redis, файлы для деплоя |

Посмотреть версию: `git checkout v0.3`. Что изменилось между версиями: `git diff v0.3 v0.4`.

Версии с паттернами устойчивости, gRPC и Kafka (v0.5 и v1.0) пока не сделаны.

## Запуск

Нужен Docker.

```
cp .env.example .env      # поменяй пароль и JWT_SECRET
make up                   # api, postgres и redis
make smoke                # проходит главный путь пользователя: нужны curl и jq
make down
```

Руками:

```
curl -X POST -d '{"email":"ann@example.com","password":"correct horse"}' localhost:8080/api/v1/auth/register
curl -X POST -d '{"email":"ann@example.com","password":"correct horse"}' localhost:8080/api/v1/auth/login
# подставь access_token из ответа
curl -H 'Authorization: Bearer <токен>' -X POST -d '{"title":"сдать отчёт"}' localhost:8080/api/v1/tasks
curl -H 'Authorization: Bearer <токен>' 'localhost:8080/api/v1/tasks?limit=10'
```

Контракт API описан в [openapi.yaml](openapi.yaml), его можно открыть в [Swagger Editor](https://editor.swagger.io/).

## v0.4 — настоящий сервис

### Чек-лист этапа

| Пункт | Где смотреть |
|-------|--------------|
| Слои handler → service → repository, зависимости через интерфейсы | `internal/httpapi`, `internal/service`, `internal/postgres`; сборка в `cmd/taskflow/main.go` |
| Роутер, валидация входа, middleware: логи, recover, request_id | `internal/httpapi/api.go`, `middleware.go`, `respond.go` |
| slog в JSON, /healthz и /readyz, graceful shutdown | `internal/logging`, `internal/httpapi/handlers.go`, `runService` в `cmd/taskflow/main.go` |
| Регистрация и логин: bcrypt + JWT access и refresh | `internal/service/auth.go` |
| Кэш горячих чтений в Redis с инвалидацией | `internal/service/tasks.go`, `internal/redisstore` |
| Юнит-тесты сервисного слоя на моках | `internal/service/*_test.go` на хранилищах из `internal/memory` |
| Проект развёрнут: HTTPS, выкатка из GitHub Actions | `deploy/`, задания `publish` и `deploy` в `.github/workflows/ci.yml` — см. «Деплой» ниже |

### Как устроено

```
cmd/taskflow            точка входа: читает настройки и собирает слои
internal/config         настройки из переменных окружения
internal/logging        JSON-логи с request_id
internal/httpapi        HTTP-слой на Gin: маршруты, middleware, перевод ошибок в статусы
internal/service        бизнес-логика: задачи с кэшем, аутентификация
internal/postgres       репозитории задач и пользователей, миграции
internal/redisstore     кэш, refresh-токены и счётчик запросов в Redis
internal/reminder       воркер напоминаний
internal/task, user     сущности и их правила
internal/memory         хранилища в памяти для юнит-тестов
internal/storetest      общие наборы тестов для хранилищ
deploy/                 боевой compose с Caddy
scripts/smoke.sh        проверка запущенного сервиса
```

Зависимости направлены внутрь: HTTP-слой знает про сервисы, сервисы — про интерфейсы хранилищ, хранилища — только про сущности. Пакет `httpapi` не импортирует pgx, пакет `postgres` не импортирует Gin.

### Настройки

Все настройки приходят из переменных окружения. Полный список печатает `taskflow` без аргументов. Обязательны три: `DATABASE_URL`, `REDIS_URL`, `JWT_SECRET`. Если что-то не задано или задано неверно, сервис не стартует и называет все проблемные переменные сразу.

### Тесты

```
make test-short   # быстрые тесты на хранилищах в памяти, без Docker
make test         # плюс репозитории на PostgreSQL в контейнере
```

Redis в тестах заменён на miniredis: он работает внутри процесса и говорит по тому же протоколу. Тесты, которые запускают сервис целиком на настоящей базе, включаются переменной `TASKFLOW_TEST_DSN`.

### Деплой

Что здесь есть и что проверено:

- **Образ публикуется в GHCR** из ветки `main` после зелёных проверок, с тегом по SHA коммита и `latest`.
- **`deploy/compose.prod.yaml`** запускает образ за Caddy: наружу открыты только порты 80 и 443, сертификат Let's Encrypt Caddy получает сам. CI поднимает эту схему с доменом `localhost` и проходит по ней `smoke.sh` через HTTPS.
- **Выкатка на сервер по SSH** описана в задании `deploy`, но ни разу не запускалась: сервера у этого репозитория нет. Задание включается, когда в настройках репозитория заданы переменная `DEPLOY_HOST` и секреты `DEPLOY_USER`, `DEPLOY_SSH_KEY`.

На сервере:

```
mkdir ~/taskflow && cd ~/taskflow
# сюда нужно положить папку deploy из репозитория и файл .env с DOMAIN=твой.домен
docker compose --env-file .env -f deploy/compose.prod.yaml up -d
```

Откат — запуск предыдущего тега: `TAG=<sha> docker compose --env-file .env -f deploy/compose.prod.yaml up -d`.

### Решения и компромиссы

- **Проверка входных данных разделена.** Формат (обязательные поля, длина, вид email) проверяет HTTP-слой тегами валидатора. Правила предметной области (заголовок не из одних пробелов, email свободен) — сервис. Ограничения в базе остаются последней линией защиты.
- **Чужая задача отвечает 404, а не 403.** Владелец входит в условие каждого запроса к базе и в ключ кэша, поэтому по ответу нельзя узнать, существует ли задача с таким id.
- **Refresh-токен — случайная строка, а не JWT.** На сервере лежит его хеш с временем жизни. Токен одноразовый: при обмене старый удаляется одной командой `GETDEL`.
- **Access-токен нельзя отозвать до истечения 15 минут.** Это цена проверки без обращения к хранилищу. Чёрного списка токенов нет.
- **Вход отвечает одинаково на неверный email и неверный пароль** и тратит на них одинаковое время: для неизвестного email пароль сравнивается с заготовленным хешем.
- **Кэшируется только чтение одной задачи.** Списки не кэшируются: фильтров много, а сбрасывать их пришлось бы при каждом изменении.
- **Недоступный Redis не ломает работу с задачами:** сервис пишет предупреждение и идёт в базу. Вход и обновление токенов без Redis не работают, поэтому `/readyz` отвечает 503.
- **Ограничение частоты входа — фиксированное окно** в минуту на IP. На границе окон оно пропускает до двойной нормы. При недоступном Redis ограничение отключается, а не блокирует вход.
- **За прокси сервис верит заголовку `X-Forwarded-For` только от адресов из `TRUSTED_PROXIES`.** Иначе клиент подставил бы любой IP и обошёл ограничение частоты.
- **CLI-команды add, list и done убраны.** У задач появились владельцы, а входа из консоли нет.
- **Пользователь `demo@taskflow.local` из v0.3 остаётся в базе без пароля:** войти под ним нельзя, его задачи недоступны через API.
- **Gin увеличил бинарник примерно вдвое** по сравнению с v0.3. Тег сборки `nomsgpack` убирает 6 МБ ненужного кода, образ остаётся меньше 30 МБ.
- **CORS не настроен:** у сервиса нет браузерного клиента.
- **Напоминания по-прежнему пишутся в лог.** Отдельный сервис уведомлений появится в v1.0.

## v0.3 — Postgres и Docker

Пути и команды ниже относятся к тегу `v0.3`.

### Чек-лист этапа

| Пункт | Где смотреть |
|-------|--------------|
| Схема users и tasks с FK, индексами и CHECK | `internal/postgres/migrations/0001_users_tasks.sql` |
| Миграции накатываются автоматически при старте | `internal/postgres/migrate.go`, команда `serve` в `cmd/taskflow/main.go` |
| Репозиторий на pgx, запросы только с плейсхолдерами | `internal/postgres/store.go` |
| Интеграционные тесты репозитория на testcontainers | `internal/postgres/store_test.go` |
| Multi-stage Dockerfile, образ меньше 30 МБ | `Dockerfile`; размер проверяет CI |
| `docker compose up` поднимает api и postgres | `compose.yaml`; запуск проверяет CI |

### Как устроено

```
cmd/taskflow            точка входа: команды, запуск и остановка сервера
internal/task           задача, ошибки и проверка входных данных
internal/postgres       репозиторий на pgx и миграции
internal/tasktest       хранилище в памяти и общий набор тестов для хранилищ
internal/httpapi        HTTP-обработчики и перевод ошибок в статусы
internal/reminder       воркер напоминаний
openapi.yaml            контракт API
Dockerfile, compose.yaml
```

### Тесты

```
make test-short   # быстрые тесты, без Docker
make test         # все тесты: PostgreSQL поднимается в контейнере сам
```

Без Docker интеграционные тесты можно направить в уже запущенную базу:

```
TASKFLOW_TEST_DSN='postgres://user:pass@localhost:5432/db?sslmode=disable' go test ./...
```

Тесты очищают таблицу `tasks`, поэтому база должна быть отдельной, не рабочей.

### Решения и компромиссы

- **Файловое хранилище удалено, а не оставлено вторым вариантом.** Две реализации пришлось бы поддерживать в каждой следующей версии.
- **Один набор тестов проходит и хранилище в памяти, и PostgreSQL** (`tasktest.RunStoreSuite`). Поэтому тестам HTTP-слоя и CLI можно доверять, хотя базы под ними нет.
- **Все задачи принадлежат одному пользователю `demo@taskflow.local`,** его создаёт вторая миграция. Таблица `users` и внешний ключ уже есть, аутентификация появится в v0.4.
- **Миграции вшиты в бинарник и накатываются при старте `serve`.** Блокировка в базе не даёт двум экземплярам мигрировать одновременно. Цена: откат делается новой миграцией, а не командой.
- **PATCH — один запрос с COALESCE** вместо сборки SQL из кусков. Плейсхолдеры остаются плейсхолдерами при любом сочетании полей.
- **Список поддерживает и offset, и курсор `after_id`.** Курсор идёт по индексу `(user_id, id)` и не замедляется с глубиной. `total` считается отдельным запросом `count(*)`: на миллионах строк его стоит убрать.
- **У воркера частичный индекс** по сроку: в нём только задачи, которые ещё ждут напоминания.
- **Два экземпляра сервиса могут отправить одно напоминание дважды:** оба успеют прочитать задачу до отметки. Для одного экземпляра это не проблема; лечится захватом строк через `FOR UPDATE SKIP LOCKED`.
- **Время наружу отдаётся в UTC,** в каком бы часовом поясе ни работал сервер.
- **Образ собран на distroless и запускается не от root.** В нём нет оболочки: зайти внутрь через `docker exec sh` нельзя, отладка идёт по логам.

## v0.2 — REST и фоновые задачи

В этой версии задачи ещё лежали в JSON-файле. Пути ниже относятся к тегу `v0.2`.

```
curl -X POST -d '{"title":"сдать отчёт","due_at":"2026-05-01T10:00:00Z"}' localhost:8080/tasks
curl 'localhost:8080/tasks?done=false&limit=10&offset=0'
curl -X PATCH -d '{"done":true}' localhost:8080/tasks/1
curl -X DELETE localhost:8080/tasks/1
```

Контракт API описан в [openapi.yaml](openapi.yaml), его можно открыть в [Swagger Editor](https://editor.swagger.io/).

### Чек-лист этапа

| Пункт | Где смотреть |
|-------|--------------|
| CRUD /tasks: список с пагинацией и фильтром, создание, PATCH, DELETE | `internal/httpapi/server.go` |
| Единый JSON ошибок и правильные статусы | `fail` и `writeError` в `internal/httpapi/server.go`, тест `TestErrors` |
| `openapi.yaml` описывает все endpoint'ы | `openapi.yaml` |
| Воркер напоминаний: пул горутин, остановка через context | `internal/reminder/worker.go` |
| `go test -race` чистый | `make test` |

### Как устроено

```
cmd/taskflow        точка входа: разбор команд, запуск и остановка сервера
internal/task       задача, ошибки и хранилище в JSON-файле
internal/httpapi    HTTP-обработчики и перевод ошибок в статусы
internal/reminder   воркер напоминаний
openapi.yaml        контракт API
```

### Решения и компромиссы

- **Пагинация через offset.** Она проще, и в файловом хранилище ей нечего ускорять. Keyset-пагинация появится вместе с PostgreSQL: там она опирается на индекс.
- **Ошибки превращаются в статусы в одном месте,** в методе `fail`. Хранилище возвращает `ErrNotFound`, `ErrEmptyTitle`, `ErrEmptyPatch` и ничего не знает про HTTP.
- **404 и 405 тоже приходят в общем формате.** Для этого зарегистрированы шаблоны без метода: стандартный роутер иначе ответил бы обычным текстом.
- **Воркер ждёт, пока обработается вся пачка, и только потом ищет задачи снова.** Так одна задача не уходит в работу дважды, хотя отметка о напоминании ставится после отправки.
- **Напоминание отправляется хотя бы один раз, но не ровно один.** Если программа упадёт между отправкой и отметкой, после перезапуска оно уйдёт повторно.
- **Упавшая отправка не отмечается** и повторяется на следующем обходе, без задержек и ограничения числа попыток. Повторы с растущей паузой — тема этапа 5.
- **Срок нельзя убрать через PATCH,** только заменить: `null` в JSON неотличим от отсутствующего поля без отдельного типа.
- **Остановка идёт по порядку:** сервер перестаёт принимать запросы и дожидается текущих, затем дожидается воркер.

## v0.1 — CLI и HTTP на stdlib

Решения первой версии. Первые два и последнее относятся к файловому хранилищу и ушли вместе с ним в v0.3, остальные действуют до сих пор:

- **Файл перечитывается и перезаписывается на каждую операцию.** Просто и надёжно для десятков задач, медленно для тысяч. На этапе 3 хранилище переезжает в PostgreSQL.
- **Запись идёт через временный файл и переименование.** Если программа упадёт посреди записи, старый файл останется целым.
- **Интерфейсы хранилища объявлены у потребителей** — в пакетах `httpapi` и `reminder`. Каждому нужна своя часть методов, и в тестах её легко подменить.
- **Текст внутренней ошибки не уходит клиенту.** В ответе — «internal error», подробности — в логе.
- **Логика команд вынесена из `main` в `run`.** Так CLI тестируется без запуска процесса.
- **Мьютекс защищает от гонок внутри одного процесса,** но не от двух процессов сразу: CLI и сервер, запущенные одновременно, могут перезаписать изменения друг друга.
